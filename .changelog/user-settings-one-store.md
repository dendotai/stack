- **User settings store, first setting `theme`** (`packages/api`, `apps/web`, `docs/adr/`, `apps/mobile/README.md`, `README.md`): one `userSettings` row per user, one read query `settings.getForCaller` that fills in the defaults, and one write mutation `settings.set` whose argument ties each key to its value type ([ADR 0010](docs/adr/0010-user-settings-one-store.md)). The first key is `theme` (`"system"`, `"light"` or `"dark"`, default `"system"`): the root loader fetches it during server render for a signed-in user, `<html data-theme>` carries it, an inline head script turns it into the `dark` class before the first paint and follows the OS for `"system"`, and a theme select in `TopNav` writes it through `useSetSetting`. The update procedure in `README.md` now says to keep one version when an entry adds something a project already does its own way. To apply: copy `convex/settings.ts`, `convex/settings.test.ts`, the `theme` validator and the `userSettings` table from `convex/schema.ts`, `apps/web/src/lib/theme.ts`, `apps/web/src/lib/use-set-setting.ts`, `apps/web/src/components/theme-select.tsx` and `apps/web/src/components/ui/native-select.tsx` with their tests, and the `__root.tsx` changes (loader, `scripts`, `data-theme`, the select in `TopNav`); the schema change only adds a table, so it deploys in one release.

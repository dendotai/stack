- **Release version from commit prefixes** (`.github/workflows/deploy.yml`, `.github/workflows/test.yml`, `package.json`, `commitlint.config.mjs`, [RELEASING.md](RELEASING.md), `CONTEXT.md`): a `dev` → `main` merge runs semantic-release before the prod deploy, which tags the release (`v1.4.2`), writes its GitHub release notes, passes the version and short commit to the web build as `VITE_WEB_VERSION` and `VITE_WEB_COMMIT`, and renames the merged `Release TBD` pull request to `Release v1.4.2`. A `commitlint` job checks the commit prefixes on pull requests into `dev`. Release pull requests merge with a merge commit. To apply: add the `release` key and the two `@commitlint/*` dev dependencies to `package.json`, copy `commitlint.config.mjs`, `RELEASING.md` and the `commitlint` job, and in `deploy.yml` copy the permissions, `fetch-depth: 0`, the main-only `cancel-in-progress`, the `Release`, `Read the release version` and `Rename the merged release PR` steps, and the two `VITE_WEB_*` build variables.
